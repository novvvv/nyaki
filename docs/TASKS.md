## 2. 동기화 기술부채

> 원인과 수정안은 [ARCHITECTURE.md 4절](ARCHITECTURE.md#4-동기화).
> **Drive 전환을 하면 A~G가 원인째 사라진다**(push/pull 코드가 없어진다) — 손대기 전에
> [DRIVE-PLAN.md](DRIVE-PLAN.md) 진행 여부를 먼저 정할 것.

### 2-1. 결함 A — 무증상 정지 (가장 급함)

push 배치에 서버가 거절하는 항목이 하나 섞이면 **그 기기의 모든 변경이 영원히 못 간다.**
`catch (_) {}`라 화면에도 로그에도 표시가 없다.

- [ ] 1단계 — 예외 로깅 + 연속 실패 카운터
- [ ] 2단계 — 임계치 초과 시 배너 (**이것만으로 무증상이 사라진다**)
- [ ] 3단계 — 4xx면 배치를 쪼개 문제 1건 격리 → **CSV·시트 가져오기를 만들기 전까지**

### 2-2. 나머지 결함

- [ ] **B 삭제 절반 전파** — 서버는 단어까지 지우면서 로그엔 단어장만 기록 → 책장 작업과 함께
- [ ] **C 로그 무한 증가** — 1년이면 새 기기 첫 동기화 12분. 단기 `hasMore`, 중기 스냅샷
- [ ] **D 부모 미확인** — 동기화 경로만 검사를 빠뜨린다
- [ ] **E 시계 신뢰** — 기기가 보낸 `updated_at`을 그대로 믿는다
- [ ] **F N+1** — pull이 로그 줄마다 조회. C를 고치면 사라짐
- [ ] **G cursor 정체** — 현재 발생 불가, 수정은 한 줄
- [ ] **`model_dump(exclude_unset=True)`** — 구버전 클라이언트가 모르는 필드를 지운다. 한 줄

### 2-3. FK는 넣지 않는다 (결론)

pull 트랜잭션이 롤백되면 cursor도 롤백되어 **동기화가 무증상으로 영구 정지**한다.
얻는 것은 앱 코드가 이미 보장하는 무결성이고 잃는 것은 영구 정지다.
