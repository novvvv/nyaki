# 성능 최적화

> 지금 당장 느리지는 않지만, 사용자 데이터가 커지면 문제가 될 곳을 모아둔다.
> 항목마다 **언제 문제가 되나**를 적어, 우선순위를 그때 판단한다.

---

## 1. 웹이 처음에 모든 단어를 한꺼번에 받는다

- [ ] 웹 첫 로딩에서 단어 내용을 빼고, 단어장을 열 때만 받기

**어디:** `web/src/lib/api-client.ts` `listBooks`, `web/src/lib/vocab-store.tsx` `refresh`

**지금 동작**

1. 로그인하면 단어장 목록을 받는다 (`GET /v1/word-books`)
2. 단어장마다 그 안의 **모든 단어**를 따로 받는다 (`GET /v1/word-books/{id}/words` × 단어장 수)
3. 묶음 담기 · 폴더 이동 실패 복구 · 단어장 삭제 등 6곳에서 이 전체를 다시 받는다 (`refresh`)

**왜 문제인가**

- 첫 화면(사이드바 · 단어장 목록)에 필요한 건 **단어장 이름과 개수**뿐이다. 개수는 서버 집계
  (`/v1/word-books/summaries`)가 이미 준다. 그런데 단어 내용 전부를 받고 있다.
- 단어 1개가 JSON으로 수백 바이트라, 단어 1만 개면 한 번에 **수 MB**를 받는다.
  폰 데이터에서는 눈에 띄게 느려지고 데이터도 쓴다.
- 단어장 수만큼 요청이 따로 나간다. 단어장 50개면 요청 51번이다.
- `refresh`가 작은 동작 뒤에도 이 전체를 다시 하므로, 담기 한 번에 수 MB를 또 받는다.

**언제 문제가 되나**

- 단어 수천 개 이상인 사용자가 생길 때. 2026-10 기준 실사용 최대 단어장은 128개라 체감되지 않는다.
- 단어 묶음 담기, AI 단어장 만들기처럼 **한 번에 많이 넣는 기능**이 생기면 빨리 온다.

**고치는 방향**

- 첫 로딩은 단어장 목록 + 서버 집계만 받는다.
- 단어 내용은 단어장 상세 화면에 들어갈 때 그 단어장 것만 받는다(이미 단어장별 API가 있다).
- `refresh` 대신 바뀐 단어장만 다시 받는다.
- 단어 목록을 쓰는 다른 화면(마이페이지의 "모은 단어" 등)은 서버 집계로 바꾼다.
