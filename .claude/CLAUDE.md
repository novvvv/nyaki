# 냐키 작업 규칙

## 커밋 · 푸시 · 배포는 사용자가 시킬 때만

**사용자가 "커밋해", "푸시해", "배포해"라고 직접 말하기 전에는 절대 하지 않는다.**

- 코드를 고친 뒤에는 무엇을 왜 바꿨는지 보고하고 **검사를 기다린다.**
- "진행해", "해봐", "다 해줘"는 코드 수정 허락이지 커밋 · 푸시 · 배포 허락이 아니다.
- 이전에 커밋 · 푸시를 허락받았어도 그건 그때 한 번뿐이다. 다음 작업에 이어지지 않는다.
- 해당하는 것
  - `git commit`, `git push`
  - `npm run deploy` (웹 → nyaki.kr, Cloudflare)
  - 푸시하면 서버(api.nyangki.com)가 자동 배포되므로 푸시도 배포다
- 할 일이 끝나면 "커밋할까요? / 푸시할까요? / 배포할까요?"로 묻고 멈춘다.

## 코드 수정

- 한 번에 파일 하나씩. 고치기 전에 무엇을 왜 바꾸는지 설명하고 승인을 받는다.
- 요청하지 않은 문구 · 버튼 · 섹션 · 크기 변경을 임의로 넣지 않는다.
