# 카드 사진 (유료) — 구조와 보안

단어마다 사진을 붙여 테스트 카드 앞 · 뒷면에 보여 주는 유료 기능이다.
사진 파일은 Cloudflare R2에 두고, 서버 DB에는 키만 적는다. 2026-11-23 도입.

- 서버: `api/app/core/photos.py`(저장소 · 키 · 권한), `api/app/vocab/photo_routes.py`(API)
- 웹: `web/src/lib/photo.ts`(줄이기), `web/src/components/word-photo-field.tsx`(사진 칸),
  `web/src/lib/api-client.ts`의 `uploadWordPhoto`
- 테스트: `api/tests/vocab/photos/test_card_photos.py`, `web/src/components/word-photo-field.test.tsx`

---

## 1. 흐름

```
웹 ─① POST /v1/words/{id}/photo/upload-url ─▶ 서버: 유료 계정 · 내 단어 · 형식 · 크기 확인
웹 ◀── 5분짜리 서명 PUT 주소 + 업로드 키(tmp/…) ──
웹 ─② PUT (사진 파일) ─────────────────────▶ R2  tmp/u/{uid}/w/{단어 해시}/{무작위}.webp
웹 ─③ PUT /v1/words/{id}/photo {key} ──────▶ 서버: 키 모양 검사 → 크기 확인 → u/…로 복사 → tmp 삭제
웹 ◀── 단어(photo_url = 하루짜리 서명 GET 주소) ──
```

- 사진 파일은 우리 서버를 거치지 않는다(브라우저 → R2 직접).
- 올리기 전에 브라우저가 긴 변 1000px webp로 줄인다(보통 100~200KB). 서버 한도는 2MB.
- 단어 추가 화면에서는 단어가 서버에 생긴 뒤에 올린다. 사진만 실패하면 단어는 저장된
  채로 알린다(다시 누르면 단어가 하나 더 생기므로 폼에 머물지 않는다).

## 2. 권한 — 누가 쓸 수 있나

- `has_card_photos(uid)` 하나로 판단한다: `PREMIUM_UIDS`에 있고 R2 설정이 다 차 있어야 한다.
  결제를 붙이면 이 함수만 결제 상태를 보도록 바꾼다.
- 화면은 `GET /v1/me/features`의 `card_photos`로만 사진 칸을 연다. **막는 건 서버다** —
  올리기 주소 · 붙이기 API가 유료가 아니면 403을 준다.
- 사진 빼기(DELETE)는 막지 않는다 — 유료가 끝난 사람도 자기 사진은 지울 수 있어야 한다.
- R2 설정이 하나라도 비면 모두에게 꺼진다. 그래서 서버를 먼저 배포해도 안전하다.

## 3. 보안 조치

| 위협 | 조치 |
|---|---|
| 버킷을 직접 열어 사진 보기 · 목록 보기 | 버킷 비공개(r2.dev 공개 주소 끔, 커스텀 도메인 없음). 보기는 서버가 서명한 주소로만 |
| 남의 사진 주소를 DB에 적어 넣기 | 사진 키는 서버만 쓰는 `words.photo_key`. 클라이언트가 보내는 `image_path`와 섞지 않는다(웹은 저장 때마다 `image_path`를 null로 보내기도 한다). 응답에는 키를 내보내지 않고 `photo_url`만 준다 |
| 남의 · 다른 단어의 업로드 키를 내 단어에 붙이기 | 붙일 때 키를 **정규식으로 전체 검사**: `tmp/u/{내 uid}/w/{이 단어 해시}/{32자 hex}.(jpg\|png\|webp)` |
| `../` · `%2e%2e` 같은 경로 조작 키 | 위 정규식이 모양 전체를 맞춰서 거절한다(앞부분만 보면 통과했다) |
| 서명 주소 조작(다른 키 · 만료 연장 · 목록) | 서명 불일치로 R2가 403. 업로드 서명에는 Content-Type이 들어 있어 형식도 못 바꾼다 |
| HTML · SVG 올려서 스크립트 실행 | 올리기 주소는 jpeg/png/webp만 발급, 서명에 형식 고정. 사진은 R2 도메인에서 열려 nyaki.kr과 출처가 다르다 |
| 큰 파일로 저장 비용 늘리기 | 서명 주소는 크기를 못 막는다 → 올리기는 `tmp/`로만. 붙일 때 크기를 재서 2MB를 넘으면 지우고 413. 정식 자리(`u/…`)에는 확인한 것만 들어간다 |
| 올리고 안 붙인 파일(고아)이 쌓임 | `tmp/`에만 남고 R2 수명 규칙 `tmp-cleanup`(접두사 `tmp/`, 1일 뒤 삭제)이 치운다 |
| 사진 속 위치 · 기기 정보(EXIF) 유출 | 브라우저가 canvas로 다시 그려 저장해서 메타데이터가 빠진다(GPS를 넣은 사진으로 실제 Chrome에서 확인) |
| 지운 뒤에도 파일이 남음 | 바꾸기 · 빼기 · 단어 삭제 · 단어장 삭제 · 동기화 삭제 때 커밋 **뒤에** R2에서 지운다(롤백되면 안 지움). 탈퇴하면 `u/{uid}/`, `tmp/u/{uid}/`를 통째로 지운다 |
| 응답이 끊겨 같은 요청을 다시 보냄 | 이미 붙인 키면 그대로 성공을 돌려준다 |
| 비밀값 노출 | R2 키는 서버 `.env`에만(권한 600). 웹 배포물에 R2 키 · 설정 이름이 없음을 확인. R2 토큰은 이 버킷의 Object Read & Write만 |

### 알고 두는 한계

- **보기 주소는 24시간짜리 bearer 링크다.** 누가 이미지 주소를 복사해 넘기면 만료 전까지
  열린다. 사진을 빼면 그 즉시 링크도 죽는다. 줄이면 앱을 오래 켜 둘 때 사진이 깨져서
  지금 값을 둔다(`VIEW_URL_SECONDS`).
- 서명 주소마다 쿼리가 달라 브라우저 캐시가 잘 안 먹는다. 사진 하나를 볼 때마다 R2 읽기
  1회(Class B, 월 1,000만 회 무료).
- 장수 제한(요금제 페이지의 1,000장 · 5,000장)은 아직 서버에서 세지 않는다.
- 요청 횟수 제한이 없다 — 유료 계정이 올리기 주소를 계속 받아 `tmp/`를 채울 수는 있다
  (하루 뒤 지워진다).

## 4. 점검 기록 (2026-11-23)

실제 R2 버킷을 상대로, 운영 서버 컨테이너 안에서 **임시 SQLite DB**로 돌렸다(운영 DB ·
실제 사진은 건드리지 않음). 가짜 계정 셋(유료 A · B, 무료 1)을 쓰고 끝나면 지웠다.
보강 전 35개 · 보강 후 40개 모두 통과, 외부 점검 2개 · EXIF 1개 통과.

- 로그인 없이 · 가짜 토큰으로 사진 API 4개 → 401
- 서명 없이 버킷 · 키 직접 접근 → 400/403
- 서명 주소: 키 변경 · 만료 연장 · 목록 · 만료 후 → 403
- 올리기 주소: 다른 Content-Type · 남의 경로 → 403. HTML · SVG 요청 → 422
- 큰 파일: tmp/에는 올라가나 붙이기 413, tmp에서 삭제, 정식 자리엔 없음
- 남의 키 붙이기 · 남의 단어에 올리기 · 빼기 → 400/404. 같은 id 단어도 서로 영향 없음
- 경로 조작 키 6종 → 400 (실제 남의 사진을 가리켜도 새지 않음)
- 무료 계정 → features false, 올리기 · 붙이기 403
- 바꾸기 · 빼기 · 단어 삭제 · 단어장 삭제 · 탈퇴 → R2에서 실제로 사라짐, 남의 파일은 그대로
- 같은 키로 다시 붙이기 → 성공

점검 스크립트는 저장소에 두지 않았다. 다시 돌릴 때는 위 항목을 그대로 따른다.

## 5. 운영 설정

**서버 `.env`** (`/opt/nyaki/api/.env`, 권한 600)

```
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET=nyaki-photos
PREMIUM_UIDS=          # 콤마로 여러 명. 결제를 붙이기 전까지 손으로 넣는다
```

`.env`를 고친 뒤에는 컨테이너를 다시 띄워야 한다(다음 배포 또는 `docker compose up -d`).

**R2 버킷 `nyaki-photos`**

- Public access: r2.dev 끔, 커스텀 도메인 없음
- CORS: `https://nyaki.kr`, `http://localhost:3000` / `PUT`, `GET` / 헤더 `Content-Type`
- 수명 규칙 `tmp-cleanup`: 접두사 `tmp/`, 1일 뒤 삭제 — **접두사를 비우면 모든 사진이 지워진다**
- API 토큰: Object Read & Write, 이 버킷만, IP 제한 없음(브라우저가 서명 주소로 직접
  올리고 보므로 IP를 막으면 다 막힌다)

**유료로 열기 전에 할 일**

- 개인정보처리방침 변경 공지(시행 7일 전) — 카드 사진 항목은 이미 들어가 있다
- 장수 제한을 서버에서 세기, 올리기 주소 요청 횟수 제한
- 결제 상태로 `has_card_photos` 바꾸기
