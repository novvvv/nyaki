# 출시 전에 반드시 해야 할 것

## 1. 이거 안 하면 스토어에서 무조건 반려됨

- [ ] **계정 삭제 버튼 만들기**
  지금은 눌러도 "준비 중"이라고만 뜬다. 로그인 기능이 있는 앱은 애플이 계정 삭제를 필수로 요구한다.
  탈퇴하면 서버에 있는 그 사람 데이터(단어장, 단어, 진행 기록, 포인트)도 같이 지워야 한다.

- [ ] **아이폰 보안 예외 설정 지우기**
  지금 설정 파일에 "암호화 안 된 통신도 허용"이라는 옵션이 켜져 있다. 원래 테스트용으로 켜둔 건데
  이걸 그대로 내면 심사에서 왜 켜져 있냐고 물어본다. 우리 서버는 이미 안전한 통신(HTTPS)을 쓰고
  있으니 그냥 이 설정을 지우면 된다.

- [ ] **개인정보처리방침 페이지 만들기**
  아직 없다. "어떤 정보를 모으고 얼마나 보관하는지" 적어놓은 페이지가 스토어 등록에 필요하다.

- [ ] **서버 설정에 남아있는 임시 주소 실제 주소로 바꾸기**
  설정 파일에 아직 "여기에 도메인 넣으세요" 같은 placeholder(자리표시자, 임시로 넣어둔 값)가
  남아있다. 이걸 실제 우리 웹사이트 주소로 바꿔야 웹에서 앱 서버 호출이 정상 작동한다.

## 2. 데이터가 사라지면 안 됨 (제일 조심해야 할 부분)

버그는 나중에 고치면 되지만, 사용자가 몇 달간 외운 단어 기록이 날아가면 되돌릴 방법이 없다.

- [ ] **실제 폰에서 업데이트 테스트하기**
  지금 앱은 데이터 저장 구조가 버전 7로 바뀌었다. 새 버전을 깐 컴퓨터 시뮬레이터가 아니라,
  **기존에 단어가 이미 저장돼 있는 실제 폰**에 새 버전을 설치해서 데이터가 안전하게 넘어가는지 확인해야 한다.

- [ ] **업데이트 도중 문제가 생겨도 앱이 꺼지지 않는지 확인**
  업데이트 중 오류가 나면 앱이 뻗을 수 있는데, 뻗으면 사용자가 앱을 지웠다 다시 깔게 되고
  그러면 폰에만 있던 데이터가 진짜로 사라진다.

- [ ] **다른 기기끼리 동기화해도 학습 기록이 안 지워지는지 확인**
  단어마다 "얼마나 외웠는지" 기록이 있는데, 이 폰에서 저 폰으로 동기화될 때 이 기록이
  초기화되지 않는지 확인해야 한다.

- [ ] **인터넷 없이 문제 풀고 나서 다시 연결됐을 때 처리 확인**
  비행기 모드처럼 인터넷이 없는 상태에서 문제를 풀면, 다시 연결됐을 때 그 결과가
  밀리지 않고 서버로 잘 올라가는지 확인.

## 3. "동기화가 조용히 멈추는 문제" — 출시 전에 최소한만 막기

지금 여러 기기 사이에 데이터를 동기화하는 코드에 이런 문제가 있다:
**한 개의 항목이라도 서버가 이상하다고 거절하면, 그 폰에서 만든 변경사항 전체가 그 뒤로 영원히
서버에 올라가지 않는다.** 그런데 이게 일어나도 화면에도, 로그에도 아무 표시가 안 뜬다.
즉 사용자도 모르고 우리도 모른다.

우리 서버가 곧 백업 역할도 하기 때문에, 이 문제가 생기면 "동기화 실패"이자 동시에 "백업 실패"다.

- [ ] **실패했을 때 최소한 기록은 남기기** (지금은 실패해도 아무 흔적이 안 남음)
- [ ] **몇 번 연속 실패하면 사용자에게 배너로 알려주기** (제일 효과 크고 제일 간단한 수정)
- [ ] **문제 있는 항목 하나 때문에 나머지까지 막히지 않게 하기** (문제 항목만 따로 떼어내기)
- [ ] 코드에서 오류를 그냥 무시하고 넘어가는 곳 4군데 손보기
- [ ] 오래된 버전 앱이 보내는 데이터 처리할 때 생기는 자잘한 버그 하나 수정

## 4. 문제 생겼을 때 원인을 찾을 방법 만들기

출시하면 "안 돼요"라는 문의가 들어올 텐데, 지금은 그 원인을 알아낼 방법이 전혀 없다.

- [ ] **앱 크래시 자동 수집 기능(Crashlytics) 연결하기** — 이미 쓰고 있는 Firebase에 포함된
  기능이라 추가 비용 없이 켤 수 있다
- [ ] **서버 쪽 오류 로그를 파일로 저장하고, 너무 쌓이면 자동 정리되게 하기**
- [ ] **로그에 이메일·비밀번호·단어 내용 같은 개인정보가 남지 않는지 확인**

## 5. 출시 전 마지막 점검 (직접 눌러보기)

      채점 → 동기화 → 로그아웃 후 재로그인까지
- [ ] 앱을 처음 설치했을 때 (아무 데이터도 없는 상태) 화면이 이상하지 않은지
- [ ] 인터넷 끊었다가 다시 연결했을 때
- [ ] 계정 삭제하고 같은 이메일로 다시 가입했을 때 예전 데이터가 안 딸려오는지

## 7. 안 쓰게 된 "구글 드라이브 백업" 화면 정리

구글 드라이브로 저장 방식을 바꾸려다 접었는데, 그때 만들어둔 화면이 아직 앱에 남아있다.
지금 눌러보면 아무 동작도 안 하는 가짜 화면이라 그대로 두면 사용자가 헷갈린다.

- [ ] 이 화면을 숨기거나 지우기 — 또는 "CSV 파일로 단어 내보내기" 기능으로 용도를 바꾸기
      (이게 제일 아깝지 않은 활용법)
- [ ] 관련된 배너·아이콘 표시도 같이 정리

# 출시하고 나서 할 것

## A. 동기화 안정화 (사용자 늘기 전에 먼저)

앞서 3번에서 급한 불만 껐다면, 여기서 나머지 원인들을 제대로 고친다.

- [ ] **동기화 기록이 계속 쌓이기만 하는 문제** — 이대로 1년 지나면 새로 로그인할 때
      동기화에 12분씩 걸릴 수 있다. **사용자가 늘어나면 제일 먼저 터질 문제**라 우선순위 1번
- [ ] 단어장을 지우면 그 안의 단어도 지워져야 하는데, 기록에는 단어장만 지운 걸로 남는 문제
- [ ] 부모 단어장이 없는 상태에서 단어가 만들어지는 걸 못 막는 문제
- [ ] 폰의 시계가 틀렸을 때 동기화 순서가 꼬이는 문제
- [ ] 위 "기록 쌓이는 문제"를 고치면 자연히 같이 해결되는 성능 문제 하나
- [ ] 지금은 발생 안 하지만 나중을 위해 미리 고쳐두면 좋은 사소한 버그 (수정 한 줄)
- [ ] **앱이 백그라운드에 있을 때 불필요하게 계속 동기화 도는 문제** — 배터리도 아끼고,
      앱을 다시 열었을 때 더 빨리 최신 상태로 보이게 하는 효과도 있음

## B. 앱 기능 채우기 (비교적 손 적게 가는 것들)

"정보" 탭에 보여주기로 한 항목 6개 중 지금 1개(암기율 그래프)만 동작한다.
나머지는 서버를 새로 안 건드리고 **폰 안에서 계산만 하면 되는 것들**이라 비용 대비 효과가 좋다.

- [ ] 전체 단어 수, 오늘 복습한 개수
- [ ] 학습 단계별 분포 (신규 / 학습 중 / 복습 중 / 완전히 외움)
- [ ] 즐겨찾기 개수, 마지막으로 공부한 날짜, 단어장 만든 날짜
- [ ] 오래 복습 안 한 단어 개수 (7일 넘은 것, 없으면 표시 안 함)
- [ ] **문제 풀다 중간에 나가도 이어서 풀기** — 채점 결과는 이미 그때그때 저장되고 있어서
      안전하지만, "어디까지 풀었는지"만 폰에 저장해두면 됨
- [ ] 문제 다 풀고 난 뒤 결과 요약 화면
- [ ] 단어에 태그(분류표) 입력하는 화면 — 데이터 저장할 곳은 있는데 입력하는 화면이 없어서
      앱에서 만든 단어는 항상 태그가 비어있음
- [ ] 로그인 화면 다듬기
- [ ] **"모름"을 한 번 눌렀을 때 점수가 너무 많이 깎이는 문제** — 50일 동안 잘 외웠던 단어도
      한 번 "모름" 누르면 거의 원점으로 돌아간다. 최소한의 바닥선을 둬야 함
- [ ] "암기했다"는 표시가 화면마다 기준이 달라서 헷갈리는 문제 통일하기

## C. 게임 요소 (재화, 연속 출석 등)

- [x] 기본 퀘스트 4개는 이미 동작 중 (냐키 쓰다듬기, 단어 추가, 아침/저녁 복습)
- [ ] **연속 출석(스트리크) 기능** — 규칙은 "그날 복습 한 번이라도 하면 인정"으로 정함.
      복습 완료 신호가 이미 있어서 구현 자체는 크지 않음
- [ ] **상점에서 실제로 아이템 사고 포인트 차감하는 기능** — 지금은 버튼만 있고 실제 구매는
      안 됨. 어떤 상품을 얼마에 팔지부터 정해야 함
- [ ] 아이템을 어떻게 저장할지 데이터 구조 정하기
- [ ] 복습 캘린더에 도장 찍는 기능 — 연속 출석 기능과 같이 설계하면 좋음

## D. "책장" 기능 (단어장을 폴더로 묶는 기능)

원래 구글 드라이브로 옮기는 김에 간단하게 만들려고 했는데, 계속 클라우드에 저장하기로 하면서
서버 쪽 작업이 다시 필요해졌다. 총 7단계 작업.

- [ ] 서버 데이터베이스에 책장 테이블 추가
- [ ] 서버 API 만들고 동기화 연결
- [ ] 위 "A. 동기화 안정화"의 삭제 관련 문제 · 부모 확인 문제를 여기서 같이 처리
      (먼저 고쳐두면 이 작업이 훨씬 안전해짐)
- [ ] 앱 쪽 데이터 저장 구조 추가
- [ ] 앱 동기화 로직 추가
- [ ] 앱 화면 (목록, 상세, 단어장 옮기기)
- [ ] 책장 단위로 테스트

> 순서: 서버 작업을 먼저 배포하고 나서 앱 작업을 해야 함.

## E. 사진 기능 (단어에 사진 첨부)

원래 계획은 구글 드라이브에 사진을 저장해서 우리 서버 비용이 안 들게 하려던 거였는데,
계속 클라우드에 저장하기로 하면서 **사진 저장 공간을 우리가 직접 만들고 비용도 우리가 부담**하게 됐다.
그래서 "사진 무제한"을 내세우려던 계획은 접어야 한다.

- [ ] 사진 저장할 서버 공간 만들기 — 비용을 어떻게 감당할지부터 정해야 함
- [ ] 사진 업로드 기능 만들고, 사용자당 용량 제한 걸기
- [ ] "서버에 올라간 사진"과 "아직 폰에만 있는 사진"을 구분해서 관리
- [ ] 업로드 실패하면 재시도하는 기능, 안 쓰는 파일 정리하는 기능
- [ ] 업로드 전에 사진 크기 줄이기 (용량 아끼려고)
- [ ] 사진 선택 버튼 실제로 동작하게 연결하기 (지금은 눌러도 반응 없음)

## F. 단어 대량 입력, 유료화

- [ ] **엑셀/CSV로 단어 한 번에 여러 개 넣는 기능** — 컴퓨터로 많은 단어를 한 번에 넣고
      싶을 때 유용함. 단, 위 "A. 동기화 기록 쌓이는 문제"를 먼저 고치고 나서 만들어야 함
      (한 번에 대량으로 넣으면 그 문제가 더 심해짐)
- [ ] 같은 단어를 중복으로 넣었을 때 걸러내는 기능
- [ ] 이상한 값(너무 긴 글자, 빈 칸, 깨진 글자)이 들어왔을 때 걸러내고 사용자에게 알려주기
- [ ] **유료화 방식 정하기** — 계속 클라우드에 저장하기로 하면서 "단어장 개수/단어 개수 제한"
      방식이 다시 가능해졌다 (서버가 사용자별 개수를 알고 있으니까). 사진 용량 제한, 유료
      재화 판매 등도 후보
- [ ] 재화를 실제로 판매하게 되면, "공짜로 받은 포인트"와 "돈 주고 산 포인트"를 구분해서
      관리하는 장치를 먼저 만들어야 함 (환불 처리 때문에 꼭 필요)

## G. 여유 있을 때

- [ ] 짧은 시간에 너무 많은 요청을 막는 장치 (지금은 없음)
- [ ] 로그아웃한 로그인 정보가 1시간 동안 계속 유효한 문제 손보기
- [ ] 오래된 데이터 구조 정리 (범위가 커서 시간 필요)
- [ ] 동기화 전체 시나리오 테스트 자동화
- [ ] 사전 찾기 기능
- [ ] 전체 디자인 리뉴얼 — 사용자 피드백 받고 나서 하는 게 효율적
- [ ] 웹사이트에 퀘스트 목록 보여주기
