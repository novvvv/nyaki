## 1. 게이미피케이션

### 1-1. 퀘스트 4개 (구현 완료)

| 퀘스트 | 조건 | 보상 |
|---|---|---|
| 냐키 쓰다듬기 | 홈 화면 탭 | 츄르 5 |
| 단어 1개 추가 | 단어 저장 | 츄르 5 |
| 아침 복습 | 06–14시(KST)에 복습 세션 완료 | 열빙어 1 |
| 저녁 복습 | 18–24시(KST)에 복습 세션 완료 | 열빙어 1 |

하루 상한은 츄르 10 · 열빙어 2. 퀘스트마다 하루 1회라 **보상표에서 자동으로 나온다** — 상한을 세는 코드가 따로 없다.

**"테스트 화면 진입" 퀘스트는 제거했다**(2026-08-27). 조건이 진입 1회뿐이라 시간 제약도 없고,
복습을 하려면 어차피 이 화면을 거친다. 아침/저녁 퀘스트를 깨는 순간 이미 만족하는 하위 퀘스트였다.

### 1-2. 서버 권위 — 단, 확인할 수 있는 것만

퀘스트 완료와 잔액은 단어장 동기화(outbox → push → LWW)를 타지 않는다.
**누적값이라 LWW로 병합할 수 없기 때문**이다 — 오프라인 두 기기가 각자 벌면 나중에 한쪽이 증발한다.

- `POST /v1/progress/quests/{id}/complete` — idempotent. 오늘 이미 완료했으면 보상 없이 현재 상태만
- `GET /v1/progress` — 잔액 + 오늘 완료된 questId 목록
- 로컬 Drift는 **순수 캐시**. 계산하지 않는다

**서버가 검증하는 것과 못 하는 것.** 복습을 실제로 했는지는 서버가 알 방법이 없다 — 앱이 보낸
완료 신호를 그대로 믿는다. 대신 서버가 아는 것은 확인한다.

| | 검증 |
|---|---|
| 복습 개수 | 불가 — 앱이 판정 |
| **지금이 그 시간대인가** | **가능** — 서버 수신 시각(KST). 기기 시계 조작이 통하지 않는다 |
| **오늘 이미 받아갔나** | **가능** — `quest_states` |

앱이 신고를 조작해도 **하루 상한 때문에 성실한 사용자보다 빨라지지 않는다.** 방어 비용이 이득보다 커서
여기까지만 한다.

### 1-3. 비로그인 — 소프트 게이트

기능을 막지 않고 **보상 수령만** 막는다.

- 퀘스트 목록은 로그인 여부와 무관하게 전부 표시 (궁금증 유지)
- 홈 고양이 탭은 항상 동작. 서버 호출만 로그인 시
- **로컬 전용 이관 로직이 통째로 불필요해진다** — 비로그인은 애초에 진행을 안 쌓으므로
  "로컬 부트스트랩 → 로그인 시 이관"의 복잡도가 사라진다. 과거 소급은 없음

### 1-4. 재화 두 종류

**츄르** — 가벼운 참여(탭 1회)의 보상.

**열빙어** — 실제 복습에만 나온다. 퀘스트가 전부 5츄르였을 때 "냐키 쓰다듬기"(탭 1회)와
"저녁 복습"(실제 학습)이 같은 값이라 **재화 가치가 행동 난이도와 안 맞았다.**

- 소비처는 **수집형·희소 아이템 전용**. 츄르로는 못 사게 막는다
- **홈에 상시 노출하지 않고 상점/마이페이지에서만** — 평소 안 보이다가 상점에서만 보이는 편이 희소성에 맞다

### 1-5. 소비처

**기각** — 힌트권(SRS 채점 정직성을 해친다. 뜻 확인을 유료화하면 모르는데도 '외움'을 누를 유인이 생긴다) ·
목표 리셋권·복습 스킵권(무료로 이미 되는 걸 재화로 막는 셈) · 스트릭 프리즈(지켜줄 streak가 아직 없다).

**채택**

1. **단어장 커버 색상/테마** — 신규 아트 불필요. 코스메틱이라 SRS 무관, 단어장이 쌓였을 때 실용적 가치도 있다
2. **캘린더 도장** — 2절과 결합. 1순위 후보
3. **냐키 액세서리** — 기존 고양이 이미지 위에 얹는 작은 오버레이 PNG

### 1-6. 결제를 붙일 때

지금은 결제가 없어 규제 리스크가 없다. **재화를 팔기로 결정하는 시점**이 곧 검토가 필요해지는 시점이다.

- **뽑기를 켜면** Apple 3.1.1이 확률 공개를 요구한다(유·무상 무관). 정찰제면 무관
- **유상 획득이 가능해지면** 국내 확률형 아이템 표시의무 대상이 될 수 있다
- **유상/무상 분리가 선결이다** — 환불·회계가 요구한다. 상세는 [DRIVE-PLAN 9-1](DRIVE-PLAN.md)

검증(조작 방지)은 규제 요건이 아니다. 무료로도 얻는 재화를 파는 건 대부분의 앱이 하는 일이다.

### 1-7. 미결정

- **인벤토리 스키마** — 아이템 1종이면 `UserProgress` 컬럼으로 충분하지만,
  액세서리·도장까지 보면 `Inventory`(itemId · count) 테이블이 낫다. 상점 착수 시 결정
- 퀘스트 목록을 서버가 내려줄지 — v1은 하드코딩 유지
- 우측 상단 플로팅 아이콘 3개(우편함 · 상점 · 뽑기) — v2+ 아이디어. 우편함은 용도부터 미정

## 2. 복습 캘린더 · 도장 (아이디어)

날짜별 복습 활동을 달력(히트맵)으로. `srsLastReviewedAt` 기준 **로컬 집계만으로 가능**하다.

**정할 것**: 어디에 넣을지(정보 탭 / 마이페이지 / 별도 화면) · streak와 시각적으로 묶을지.
streak가 생기면 연속 학습일을 달력 위에 하이라이트하는 조합이 자연스러워 **같이 설계하는 편이 낫다.**

**캘린더 도장** — 재화로 산 도장(하트·발바닥·계절 테마)을 그날 칸에 찍는다.
캘린더와 상점 백로그를 하나로 묶는 아이디어라 효율적이고, SRS 정직성과 무관한 코스메틱이라 안전하다.

**도장 도감** — 모은 도장을 보는 화면. 보유는 컬러, 미보유는 실루엣, "24/40 수집" 진행률.
두 재화가 자연스럽게 갈린다 — 일반 도장은 츄르, **희귀·시즌 도장은 열빙어 전용.**

→ 캘린더 하나로 **매일 쓰는 재미(도장) + 모으는 재미(도감) + 두 재화의 용도 분리**가 엮인다.

**우선순위 낮음**: 단어 카드/스티커(어디에 고정할지 애매해 설계 부담이 크다) ·
단어장 표지 꾸미기 확장(색상을 먼저 하고 나중에 패턴으로 넓히는 편이 낫다)
